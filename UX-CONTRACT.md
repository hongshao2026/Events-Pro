# Events Pro selector behavior

## Product and source

Current user requirements and PRODUCT.md override the earlier event-grouped list and desktop layout. Starting flights are separate: 75 original events become 102 entries; 11 optional satellites bring the total to 113. My schedule adds 23 conditional continuation activities, yielding 125 original activities or 136 with supplements. Each flight has an independent status. USD and VND use exact native amounts; parenthesized estimates use the saved display currency and editable local rate table. Same currencies and original-only preference omit conversion. Currency totals are never added together. Budget defaults to one buy-in per attending flight, with a persistent alternative counting each event once. Guarantees are shared by flights and never summed. Selection does not register with the casino. Local-only delivery remains authoritative.

## Optional account workflow (disabled by default)

Source: the 2026-10-02 user request and email-OTP choice in PRODUCT.md; provider contracts and deployment boundary are documented in AUTH.md. Offline delivery and the existing planner remain public and unchanged by account state. Authentication is never enabled by a hash/query parameter. Only an explicit build flag on HTTP(S) can load the auth module; file delivery is always disabled, with no SDK initialization or auth requests.

Canonical Form owner: components/auth/account-control.tsx and lib/auth/config.ts. Canonical Account/Session owner: lib/auth/client.ts and components/auth/auth-app.tsx. Canonical Overlay remains components/ui/sheet.tsx (account variant); shared toast, focus styles and global scrollbars remain unchanged. Forms use noValidate, visible labels, first-error focus, linked inline errors, masked/revealable OTP, autofill/paste support and IME guards. Pending requests block duplicate actions; a 60-second email cooldown survives closing the sheet. The latest sent-to address remains only in the current page's state; the typed code is discarded on close. Failed verification preserves input for correction.

Google authorization is user-triggered PKCE. Callback credentials are removed before Planner mounts. Return navigation restores only the original same-origin path and allowlisted planner hash fields, including the selected series and homepage region. Cancellation and expired callback offer retry/email fallback. No provider errors or credentials are rendered verbatim. Initialization/configuration failures leave the local planner usable. On refresh, SDK session restoration precedes account display. SDK refresh and cross-tab auth events update the account; an ended session offers reauthentication without losing local selections. Logout stays pending until the SDK finishes and never clears planner storage. The pinned SDK also clears local auth when remote revocation fails; the UI explicitly distinguishes local sign-out from unconfirmed server revocation and never restores old tokens. No protected remote business data or client-authorized role gates are introduced.

## State and recovery

The delivered HTML contains all assets and schedule data. It runs directly from file:// without a server, login, remote API, or external resources. CSP denies network connections. Explicit source links are user initiated. The Triton source PDF is embedded in the offline bundle and downloadable without network access.

Browser localStorage is authoritative; the UI commits only after successful setItem. Storage or parse failures retain the raw record and show recovery. Version 2 uses poker-planner-local-v2. The v1 key is retained and converted as defined in PRODUCT.md. Unassigned old attendance stays pending; no flight is guessed. A whole-state revision is reread before updates; stale changes reject and refresh. Storage/visibility events refresh other tabs. localStorage has no transaction guarantee for perfectly simultaneous writes.

Export includes selections, pending legacy attendance and budget mode. Restore validates schema, known IDs, statuses, revisions, consistency and file size; previews date/counts in a Radix alert dialog; then replaces data only on confirmation and successful local write. Invalid imports, cancel and write errors preserve current data. Restore errors appear inside the dialog; save errors remain visible in an open cart. Clearing browser data, changing browser or moving the HTML requires a backup.

## Navigation, locale and accessibility

The default view is the series homepage (view=home). Region options are all, apac, north-america, south-america and europe; the URL region parameter restores the selection. All regions means one combined catalog, ascending by start date and grouped by starting month, not grouped by region first. The catalog contains QPC Circuit Hanoi (APAC / Vietnam), Triton ONE North Cyprus (Europe in the product's region grouping) and Wynn WPT (North America / US), in that date order. No invented series appear in empty regions. Cards use native links with view=discover and a stable series ID; normal click opens the detailed schedule, and modified clicks retain browser link behavior. A back link and the Events bottom navigation return to the homepage. Region choice survives entering a series, returning and reloading. Invalid regions become all; unknown series show an explicit recovery page. Logo images are bundled in the HTML and fall back to brand text on failure. Adding future live series also requires their own schedule, bounds, currency and time-zone integration; catalog metadata alone does not implement that data pipeline.

Search, OR categories, inclusive date range, other filters and page belong to URL hash parameters for file:// compatibility. Legacy status/date hashes are recognized. Local search waits for IME composition end; clear is immediate. 15 flights/page, page clamps when results shrink. Budget includes all attending records independent of filters. Category filters use OR, other filters use AND. All-checkbox is checked/indeterminate/unchecked; no statuses selected produces an actionable empty state. Hide skipped removes only skip; filter changes never mutate saved classifications.

Discovery: all dates precedes its calendar popover. DayPicker uses full zh-CN locale, date-only values and navigation bounded by the selected series. A day or range stays draft until Apply. Cancel/Escape retains the old filter. The phone canvas shows one month, with planned-day dots. Discovery filters concern starting dates.

My schedule: a dedicated page selected by bottom navigation. The single-month calendar covers the same festival; selecting a day immediately displays and scrolls to that day's rows. Selecting the same date again retains it; the explicit all-dates button clears the choice. All dates shows every date group. Date dots and counts reflect the current agenda categories and continuation/supplement choices. Per the latest calendar requirement in PRODUCT.md, agenda categories are independent of discovery filters and restricted to attend/watch, both enabled by default. StatusFilter uses its shortlist variant; undecided and skip are excluded from rows, date dots and counts even for legacy URLs. Legacy unsupported-only status links fall back to attend+watch, while explicit none preserves an empty filter. Empty-state recovery stays within attend+watch. A successful reclassification to undecided/skip immediately removes the row and its calendar contribution; the open detail remains usable until closed, then focus falls back to the agenda summary. Discovery retains all four categories. Hash fields view, day, agendaStatuses, continuations and month restore the page and its choices on reload; existing discovery hashes remain valid. Calendar state and discovery filters survive switching pages. Browser Back/Forward updates the view. Each activity is one row sorted by day/time and opens a modal detail. Starting-row detail offers the shared four classifications; continuation detail directs to its starting flights.

Continuation activities appear once even if multiple starting flights are selected. Status precedence is any attend (including pending legacy attendance), then any watch, then skip only if all starting flights are skip, otherwise undecided. They are conditional on qualifying and have zero added buy-in. The UI labels them explicitly, and shows their actual date/time. No new storage schema or guessed flight assignment is introduced.

My shortlist is a Radix modal sheet, grouped by start day. Attend and watch enter the list; only attendance enters budget. Row actions are shared across discovery, agenda and shortlist. Pending legacy records offer a choose-flight path. Cart has category views and budget mode. No fake other festivals, billing, advertisements or cloud synchronization are exposed.

zh-CN interface and aria labels, en-US grouped USD/VND amounts, series-local dates (WPT PST; Triton North Cyprus EET; QPC Hanoi ICT). Native button/link semantics, visible keyboard focus, Radix controls, text plus status color and phone layout. Empty results have recovery. Errors persist until resolved. No native alert/confirm/prompt. Calendar and sheet return focus on close. Main page scrolls naturally; only sheet body and calendar popup scroll within viewport bounds. Reduced motion disables transitions. Feature-detected browser tools target flight IDs.

## Profile and local administration

Routes view=profile and view=admin retain the current series and all discovery/agenda choices. The fourth bottom item opens profile; its management link opens two Radix tabs. Local username and currency persist independently of auth. AuthApp projects only display-safe account information; authentication flags and cloud behavior stay unchanged. VIP 0 is a base display without entitlement claims.

Settings use events-pro-settings-v1 with strict validation, revisions, storage/visibility refresh and a separate confirmed backup restore. Existing poker-planner-local-v2 and its backups retain their schema. Invalid or failed writes preserve existing records and editable drafts. Form baselines detect stale saves; explicit reload/reopen recovers. Unsaved fields require discard confirmation for app navigation, tabs, sheet close and browser Back; page reload/close uses the native beforeunload safeguard.

SettingsProvider derives a managed catalog from immutable imported events plus overrides; all planner budgets and agenda use that catalog. Hiding removes an event from discovery and home counts, but retains existing attendance, watch rows, budgets and continuations. Restoring official data removes only overrides. Currency filters remain native. Rate settings use CNY per unit, with 1000 VND per input for readability, a saved date and source. Cross-conversion is nativeAmount × sourceRate / targetRate. Approximate amounts are fixed to two decimals (VND integers); no-rate, same-currency and original-only cases are explicit.
