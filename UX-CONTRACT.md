# Events Pro selector behavior

## Product and source

Current user requirements and PRODUCT.md override the earlier event-grouped list and desktop layout. WPT starting flights are separate: 75 original events become 102 entries; 11 optional satellites bring the total to 113. My schedule adds 23 conditional continuation activities, yielding 125 original activities or 136 with supplements. Each flight has an independent status. USD, VND and KRW use exact native amounts; parenthesized estimates use the saved display currency and editable local rate table. Same currencies and original-only preference omit conversion. Currency totals are never added together. Budget defaults to one buy-in per attending flight, with a persistent alternative counting each event once. Guarantees are shared by flights and never summed. Selection does not register with the casino. Local-only delivery remains authoritative.

## Optional account workflow (disabled by default)

Source: the 2026-10-02 user request and email-OTP choice in PRODUCT.md; provider contracts and deployment boundary are documented in AUTH.md. Offline delivery and the existing planner remain public and unchanged by account state. Authentication is never enabled by a hash/query parameter. Only an explicit build flag on HTTP(S) can load the auth module; file delivery is always disabled, with no SDK initialization or auth requests.

Canonical Form owner: components/auth/account-control.tsx and lib/auth/config.ts. Canonical Account/Session owner: lib/auth/client.ts and components/auth/auth-app.tsx. Canonical Overlay remains components/ui/sheet.tsx (account variant); shared toast, focus styles and global scrollbars remain unchanged. Forms use noValidate, visible labels, first-error focus, linked inline errors, masked/revealable OTP, autofill/paste support and IME guards. Pending requests block duplicate actions; a 60-second email cooldown survives closing the sheet. The latest sent-to address remains only in the current page's state; the typed code is discarded on close. Failed verification preserves input for correction.

Google authorization is user-triggered PKCE. Callback credentials are removed before Planner mounts. Return navigation restores only the original same-origin path and allowlisted planner hash fields, including the selected series and homepage region. Cancellation and expired callback offer retry/email fallback. No provider errors or credentials are rendered verbatim. Initialization/configuration failures leave the local planner usable. On refresh, SDK session restoration precedes account display. SDK refresh and cross-tab auth events update the account; an ended session offers reauthentication without losing local selections. Logout stays pending until the SDK finishes and never clears planner storage. The pinned SDK also clears local auth when remote revocation fails; the UI explicitly distinguishes local sign-out from unconfirmed server revocation and never restores old tokens. No protected remote business data or client-authorized role gates are introduced.

## State and recovery

The delivered HTML contains all assets and schedule data. It runs directly from file:// without a server, login, remote API, or external resources. CSP denies network connections. Explicit source links are user initiated. The Triton and JPF source PDFs are embedded in the offline bundle and downloadable without network access.

Browser localStorage is authoritative; the UI commits only after successful setItem. Storage or parse failures retain the raw record and show recovery. Version 2 uses poker-planner-local-v2. The v1 key is retained and converted as defined in PRODUCT.md. Unassigned old attendance stays pending; no flight is guessed. A whole-state revision is reread before updates; stale changes reject and refresh. Storage/visibility events refresh other tabs. localStorage has no transaction guarantee for perfectly simultaneous writes.

JSON backup export includes selections, pending legacy attendance and budget mode. Restore validates schema, known IDs, statuses, revisions, consistency and file size; previews date/counts in a Radix alert dialog; then replaces data only on confirmation and successful local write. Invalid imports, cancel and write errors preserve current data. Restore errors appear inside the dialog; save errors remain visible on the shortlist and in an open detail. Clearing browser data, changing browser or moving the HTML requires a backup. A shortlist PNG is a viewing/sharing artifact and does not replace this restorable backup.

## Navigation, locale and accessibility

The default view is the series homepage (view=home). Region options are all, apac, north-america, south-america and europe; the URL region parameter restores the selection. All regions means one combined catalog, ascending by start date and grouped by starting month, not grouped by region first. The catalog contains QPC Circuit Hanoi (APAC / Vietnam), Jeju Poker Festival (APAC / South Korea), Triton ONE North Cyprus (Europe in the product's region grouping) and Wynn WPT (North America / US), in that date order. No invented series appear in empty regions. Cards use native links with view=discover and a stable series ID; normal click opens the detailed schedule, and modified clicks retain browser link behavior. A back link and the Events bottom navigation return to the homepage. Region choice survives entering a series, returning and reloading. Invalid regions become all; unknown series show an explicit recovery page. Logo images are bundled in the HTML and fall back to brand text on failure. Adding future live series also requires their own schedule, bounds, currency and time-zone integration; catalog metadata alone does not implement that data pipeline.

Search, OR categories, inclusive date range, other filters and page belong to URL hash parameters for file:// compatibility. Legacy status/date hashes are recognized. Local search waits for IME composition end; clear is immediate. 15 flights/page, page clamps when results shrink. Budget includes all attending records independent of filters. Category filters use OR, other filters use AND. All-checkbox is checked/indeterminate/unchecked; no statuses selected produces an actionable empty state. Hide skipped removes only skip; filter changes never mutate saved classifications.

Discovery: all dates precedes its calendar popover. DayPicker uses full zh-CN locale, date-only values and navigation bounded by the selected series. A day or range stays draft until Apply. Cancel/Escape retains the old filter. The phone canvas shows one month, with planned-day dots. Discovery filters concern starting dates.

My schedule: a dedicated page selected by bottom navigation. The single-month calendar covers the same festival; selecting a day immediately displays and scrolls to that day's rows. Selecting the same date again retains it; the explicit all-dates button clears the choice. All dates shows every date group. Date dots and counts reflect the current agenda categories and continuation/supplement choices. Per the latest calendar requirement in PRODUCT.md, agenda categories are independent of discovery filters and restricted to attend/watch, both enabled by default. StatusFilter uses its shortlist variant; undecided and skip are excluded from rows, date dots and counts even for legacy URLs. Legacy unsupported-only status links fall back to attend+watch, while explicit none preserves an empty filter. Empty-state recovery stays within attend+watch. A successful reclassification to undecided/skip immediately removes the row and its calendar contribution; the open detail remains usable until closed, then focus falls back to the agenda summary. Discovery retains all four categories. Hash fields view, day, agendaStatuses, continuations and month restore the page and its choices on reload; existing discovery hashes remain valid. Calendar state and discovery filters survive switching pages. Browser Back/Forward updates the view. Each activity is one row sorted by day/time and opens a modal detail. Starting-row detail offers the shared four classifications; continuation detail directs to its starting flights.

Continuation activities appear once even if multiple starting flights are selected. Status precedence is any attend (including pending legacy attendance), then any watch, then skip only if all starting flights are skip, otherwise undecided. They are conditional on qualifying and have zero added buy-in. The UI labels them explicitly, and shows their actual date/time. No new storage schema or guessed flight assignment is introduced.

My shortlist is a dedicated route (view=shortlist) opened by the bottom navigation's Table2 control. Both shortlist and schedule have table/calendar buttons that navigate between these existing routes; route history, discovery filters and calendar choices remain intact. The shortlist is cross-series even while the calendar is scoped to one selected series. The former cart Sheet and its trigger are removed. The user's whole-plan sharing request is implemented as the local image export described below.

MyShortlist renders the finite, locally bundled selection set in a native table, ordered by local start date/time with series-local timezone labels. There is no remote paging, load-more or infinite loading; render-all is intentional because rows are bounded by the bundled entry catalog plus one pending row per legacy event. Any future unbounded server-backed catalog must revisit this strategy. The fixed left event-name column is 154px. Remaining columns are time, buy-in, status, counted budget, guarantee/seats and series/location. Horizontal overflow belongs only to a named, keyboard-focusable table container with a visible swipe hint; document scrolling continues to own the vertical page. Narrow viewports retain all columns through horizontal scrolling, not by hiding data or widening the page. Buttons in the first column open the canonical Sheet with shared EntryDetails and EntryActions; close restores the row's focus or the table summary if reclassification removed it. Attend/watch are the only saved classifications shown, while the four shared classification actions remain available in detail. Empty selection offers a path to discover events, and an empty category filter offers a return to all selections.

The all/attend/watch display category is transient component state. This is an explicit URL-persistence exception for the current local planning architecture: it narrows only this visit's table, is not part of a shareable query or a saved plan, and resets to all when the page remounts. It never mutates selections, discovery/agenda filters or the cross-series budget summary. Budget mode remains persistent in local state and backup. Per PRODUCT.md, lib/shortlist.ts attributes the existing budget to rows: per-flight mode counts each attendance row; per-event mode counts only the selected row with the largest buy-in, breaking equal-price ties by earliest date/time. Other selected flights explain that their amount was merged; watch rows contribute zero. Pending legacy attendance appears once with an explicit unassigned-start label, contributes once under the existing budget rule, and offers choose-flight/remove actions without guessing a date or flight. Numeric row contributions across the complete table equal lib/local-store.ts budget().totals within each native currency. Unknown fees are distinct from zero: they display 未公布, are excluded from numeric totals and contribute to the budget helper's unknownCount. Event mode selects the greatest known attending fee, or keeps the event unknown if all its attending fees are unknown. Both the table and export use SettingsProvider's managed catalog, including renamed or repriced events and existing selections that have been hidden from discovery. Storage schema, migration, FX, backup and commitment-on-write rules do not change. No fake other festivals, billing, advertisements or cloud synchronization are exposed.

Shortlist detail variant: a successful classification change that removes the row from the active table filter closes its detail and returns focus to the shortlist summary. Failed writes keep the detail open and the previous classification intact. Agenda detail retains its established stay-open behavior.

Shortlist image export follows PRODUCT.md's 2026-10-08 follow-up. “导出图片” captures a snapshot of all selected attend/watch entries and pending legacy attendance across every bundled series, in the same local-date/time order and with the same row budget attribution as the complete table. All seven columns are included, together with separate native USD/VND/KRW budget subtotals and optional estimates in the saved display currency, the current budget mode, local-time labels and personal-plan/non-registration guidance. Category filters, selected series, horizontal scroll and viewport dimensions do not limit the exported data. Existing guarantees remain shared, watch rows contribute zero, and pending rows retain their unassigned-start label. The snapshot uses the current managed event data and saved display-currency/rate settings; original-only and same-currency preferences omit conversion, missing rates remain explicit, and unknown fees retain the 未公布 label and excluded-fee count. Export never mutates saved selections, budget mode or backup data.

The export action is disabled for an empty plan, unavailable planner state and while generating. A stable busy label exposes progress and duplicate triggers are ignored. The local renderer allows a bounded wait for font readiness, creates a single PNG without fetching assets, and targets 2× resolution with bounded canvas dimensions (maximum edge 8,192 pixels and total area 12 megapixels); long plans scale to fit rather than omit rows. Smaller canvas retries may recover from allocation or encoding failure, still preserving the full table. A successful render opens the canonical modal Sheet with the image and initiates a browser download. “保存图片” retries the same image download without regenerating; on supported touch browsers, the displayed image also allows long-press saving. Generated-image feedback must not claim the browser has saved the file or added it to a photo album. No Web Share API, platform SDK, remote upload or external messaging is introduced.

The preview has an accessible title/description, full-plan image alternative text, a visible close control, Escape handling and focus restoration to the export trigger. Its body scrolls internally while save controls remain reachable. Rendering failure retains the plan, shows a persistent inline error and permits retry. Download failure leaves the generated preview available for retry or long-press saving. Preview object URLs are revoked on close or unmount; stale completion after leaving the page does not open a preview or trigger a download. Rendering and preview use the canonical CSS token palette, shared Sheet and existing local state/budget helpers.

zh-CN interface and aria labels, en-US grouped USD/VND/KRW amounts, series-local dates (WPT PST; Triton North Cyprus EET; QPC Hanoi ICT; Jeju KST). Native button/link semantics, visible keyboard focus, Radix controls, text plus status color and phone layout. Empty results have recovery. Errors persist until resolved. No native alert/confirm/prompt. Calendar and sheet return focus on close. Main page scrolls naturally; sheet bodies and calendar popup scroll within viewport bounds, and the shortlist table independently scrolls horizontally. Reduced motion disables transitions. Feature-detected browser tools target flight IDs.
